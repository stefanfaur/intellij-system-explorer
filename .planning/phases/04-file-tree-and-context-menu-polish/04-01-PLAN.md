4. **Add VCS color helper** as a private method in FileTreeComponent (not inside the renderer):
   ```kotlin
   private fun getEffectiveVcsColor(vf: VirtualFile): Color? {
       return try {
           if (vf.isDirectory) {
               directoryStatusCache.getOrPut(vf.path) {
                   // 1-level propagation: check immediate children only
                   val children = vf.children ?: return@getOrPut null
                   for (child in children) {
                       val status = FileStatusManager.getInstance(project).getStatus(child)
                       if (status != FileStatus.NOT_CHANGED) {
                           return@getOrPut status.color
                       }
                   }
                   null
               }
           } else {
               val status = FileStatusManager.getInstance(project).getStatus(vf)
               if (status == FileStatus.NOT_CHANGED) null else status.color
           }
       } catch (_: Exception) { null }
   }
   ```
   IMPORTANT: `getOrPut` with a nullable value — `ConcurrentHashMap` does not store null values. To handle directories with no VCS color, use a sentinel approach: store `Color.BLACK` (or any non-null) and check, OR use a separate `HashSet<String>` for "checked but null" paths. The simplest fix: use a regular HashMap synchronized on access, or change the cache to `ConcurrentHashMap<String, Optional<Color>>`. Use `Optional.empty()` for "no color" and `Optional.of(color)` for a color. This avoids the ConcurrentHashMap null-value pitfall.

   Revised approach — use `java.util.Optional`:
   ```kotlin
   private val directoryStatusCache = ConcurrentHashMap<String, java.util.Optional<Color>>()
   ```
   And in getEffectiveVcsColor:
   ```kotlin
   if (vf.isDirectory) {
       val cached = directoryStatusCache[vf.path]
       if (cached != null) return cached.orElse(null)
       // compute...
       directoryStatusCache[vf.path] = java.util.Optional.ofNullable(color)
       return color
   }
   ```

   ```kotlin
   override fun treeWillCollapse(event: TreeExpansionEvent) {
       val node = event.path.lastPathComponent as? DefaultMutableTreeNode ?: return
       val file = node.userObject as? VirtualFile ?: return
       if (!file.isDirectory) return
       // Restore placeholder so treeWillExpand guard fires correctly on re-expansion.
       // Use invokeLater to avoid modifying the model during Swing's collapse processing.
       ApplicationManager.getApplication().invokeLater {
           if (isDisposed) return@invokeLater
           node.removeAllChildren()
           node.add(DefaultMutableTreeNode("loading..."))
           treeModel.nodeStructureChanged(node)
       }
   }
   ```
   This ensures that when a directory is collapsed, its children are replaced with the "loading..." placeholder. On re-expand, the `treeWillExpand` guard (`childCount != 1 || userObject !is String`) correctly fires the lazy load, preventing duplicate children.
