The new menu structure follows the locked decision from CONTEXT.md. Replace the entire body of createPopupMenu() with:

**Group 1: Open actions**
- "Open" — enabled when singleFile is non-null and NOT a directory. Opens in editor.
- "Open in System" — enabled when singleFile is non-null AND Desktop.Action.OPEN is supported. Opens with OS default app (existing logic).
- Reveal action — OS-adaptive label using SystemInfo (already imported):
  ```kotlin
  val revealLabel = when {
      SystemInfo.isMac     -> "Reveal in Finder"
      SystemInfo.isWindows -> "Reveal in Explorer"
      else                 -> "Open in File Manager"
  }
  ```
  Enabled when singleFile is non-null AND `Desktop.isDesktopSupported() && Desktop.getDesktop().isSupported(Desktop.Action.BROWSE_FILE_DIR)`.
  Action listener: run off EDT via `AppExecutorUtil.getAppExecutorService().execute { ... }`, call `Desktop.getDesktop().browseFileDirectory(java.io.File(singleFile.path))`. Wrap in runCatching with LOG.warn on failure.
- "Open Terminal Here" — enabled when singleFile is non-null OR contextDir is non-null. Action listener:
  ```kotlin
  val dir = if (singleFile?.isDirectory == true) singleFile.path
            else singleFile?.parent?.path ?: contextDir?.path ?: return@addActionListener
  try {
      TerminalToolWindowManager.getInstance(project).createLocalShellWidget(
          dir, "Terminal: ${java.io.File(dir).name}", true, true
      )
  } catch (e: Exception) {
      LOG.warn("Failed to open terminal: ${e.message}")
  }
  ```

**Enable/disable consistency (CTX-04):** Every menu item must set its `isEnabled` property explicitly based on selection state. Items should still be VISIBLE even when disabled (don't conditionally add/remove items based on selection — add all items, set isEnabled). Exception: "Open" (files only) can still be conditionally added since it makes no sense for directories. Same for "Add to Bookmarks" which is directory-only.

Actually, per the existing pattern and user expectation: keep the conditional-add pattern for items that are semantically invalid (Open for dirs, Add to Bookmarks for files). For items that are temporarily unavailable (Paste with empty clipboard, etc.), show disabled. The key change from CTX-04 is that ALL clipboard/file actions should be present in the menu regardless, with correct enabled state — no items should mysteriously appear/disappear based on selection other than the Open/Bookmark cases.

Revised approach: Add ALL items always, set `isEnabled` based on conditions. For "Open" set `isEnabled = singleFile != null && !singleFile.isDirectory`. For "Add to Bookmarks" set `isEnabled = singleFile?.isDirectory == true`.
